DSRUL A/C/D 三模式服务器使用说明

实验身份
========

分支：experiment-d-oracle-soft-diagnostics
版本：2.0.0-experiment.d-oracle-soft-diagnostics
基线：experiment-c-preupdate-proposal@ec77f6f

本版本用同一套训练、评估和诊断代码运行三种模式：

baseline    = A：当前 batch 先更新原型，再提出 batch-local 重标。
preupdate   = C：先用旧原型提出重标，再更新原型。
oracle_soft = D：沿用 C 的顺序；观测标签正确样本权重 1.0，已知错误标签
              样本默认权重 0.5。

D 只用于判断“原型软去噪是否存在上限”，不是可部署方法。干净训练标签在 A/C
中只做 detached 统计；在 D 中额外生成原型权重。它不会成为 CCAR 或 DSRUC
损失目标，样本也始终归入其观测标签对应的原型类别。

目录要求
========

/新数据集/raf-basic/EmoLabel/list_patition_label.txt

运行前检查
==========

在上传后的代码根目录执行：

/DSRUL_code/.venv/bin/python3 -m compileall -q src
/DSRUL_code/.venv/bin/python3 -m unittest discover -s src -p "test_*.py" -v
/DSRUL_code/.venv/bin/python3 src/train_rafdb.py --help

应看到 29 项测试通过，并且 --help 中存在：

--ccar_variant {baseline,preupdate,oracle_soft}
--oracle_noisy_weight
--seed

推荐的验证实验
==============

run_rafdb_matrix.sh 默认顺序运行 A/C/D × seed 0/1/2，共 9 次训练。所有运行固定
split_seed=0，并使用 --skip_test_eval，因此调参阶段不会访问官方测试集。

先给结果根目录加上本次时间，避免覆盖：

chmod +x run_rafdb_matrix.sh
RESULT_ROOT=/result/rafdb_noise0.1_ACD_YYYYMMDD_HHMMSS \
  ./run_rafdb_matrix.sh

也可以先做单个烟雾测试：

SEEDS="0" VARIANTS="oracle_soft" \
RESULT_ROOT=/result/rafdb_noise0.1_D_smoke_YYYYMMDD_HHMMSS \
  ./run_rafdb_matrix.sh

不要用旧 A/C 的 seed 0 结果替代新矩阵中的 seed 0：本版本改为显式、独立地
控制 sampler 和 worker 随机流，旧结果与新 seed 协议不属于同一配对实验。

启动身份核验
============

每次启动必须看到：

Implementation version: 2.0.0-experiment.d-oracle-soft-diagnostics
Method contract: {... 'ccar_variant': '<本次模式>' ...}

D 还必须看到：

'prototype_update_weighting': 'oracle_clean_soft'
'oracle_noisy_weight': 0.5

每轮日志应包含 Component losses 和 Relabel diagnostics。若版本、模式、seed 或
权重与命令不一致，立即停止该次训练。

输出文件
========

每个 save_dir 至少包含：

best.pth
metrics.jsonl
run_manifest.json
split_manifest.json
train.log

metrics.jsonl 每轮记录：三项损失、重标总数、正确纠错、误改干净样本、
错误改成另一错误类、逐类别计数、原型范数/漂移、更新覆盖、权重和、本轮权重
ESS 代理，
以及验证集 accuracy、macro-F1、balanced accuracy、逐类 recall 和混淆矩阵。

run_rafdb_matrix.sh 默认跳过官方测试，因此不会产生 test_metrics.json 和
test_predictions.csv。完成多 seed 验证选择后，只对最终选定方案用新的结果目录
重跑一次：

SEEDS="1" VARIANTS="oracle_soft" SKIP_TEST_EVAL=0 \
RESULT_ROOT=/result/rafdb_noise0.1_final_YYYYMMDD_HHMMSS \
  ./run_rafdb_matrix.sh

最终会额外生成这两个文件。脚本会拒绝复用已有非空 save_dir，避免日志、manifest
和 checkpoint 被覆盖或混在一起。

结果判定
========

1. 先比较三个 seed 的最佳验证指标、均值、标准差和逐 seed 的配对差值。
2. 如果 C 对 A 不稳定，仍以 A 为基线。
3. 如果 D（oracle_soft）仍不能稳定优于对应基线，停止原型过滤方向。
4. 只有 D 显示稳定上限时，才继续开发不使用真值的时间置信度软权重。

注意事项
========

1. 三种模式不得共用 save_dir。
2. --split_seed 固定为 0；--seed 才是训练随机种子。
3. 不要把 D 写成实际可部署方法或论文原方法。
4. A/C/D 的完整 checkpoint method contract 不同，不能交叉 --checkpoint 恢复；
   兼容权重只能通过 --pretrained warm start。
5. 保存完整结果目录、终端日志、代码版本和预训练权重校验值。
